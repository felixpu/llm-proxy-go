# Hotpath A/B 基准报告（2026-04-14 13:45）

## 背景

本报告对比以下两组路径：

- 旧路径近似（`old`）：`Direct + ShadowSyncApprox`，`API Detect cache_miss_unique_model`
- 当前实现（`new`）：`Direct + ShadowAsync`，`API Detect cache_hit`

说明：`ShadowSyncApprox` 是“旧版同步 shadow”的近似基准，不代表历史二进制逐字节复现。

## 测试环境

- 机器：macOS 12.7.6
- CPU：Intel(R) Core(TM) i7-8750H CPU @ 2.20GHz
- Go 包：`github.com/user/llm-proxy-go/internal/service`
- 参数：`BENCH_TIME=1s BENCH_COUNT=6`

## 核心结果（sec/op）

| 场景 | old | new | 变化 |
|---|---:|---:|---:|
| `HotPathEndpointSelector_DirectModel_Shadow-12` | `7.646µs` | `4.326µs` | `-43.42%` |
| `HotPathEndpointSelector_DirectModel_NoShadow-12` | `538.9ns` | `521.9ns` | `~` |
| `HotPathAPIDetectCache/lookup-12` | `92,973.5ns` | `473.9ns` | `-99.49%` |

统计显著性（benchstat）：

- Shadow 场景：`p=0.002`
- API Detect 场景：`p=0.002`
- NoShadow 场景：`p=0.818`（无显著变化）

## 代价与权衡

Shadow 异步化在该基准下有内存与分配开销上升：

- `B/op`：`+12.70%`
- `allocs/op`：`+12.31%`

API Detect 缓存命中显著降低开销：

- `B/op`：`-99.36%`
- `allocs/op`：`-99.19%`

## 结论

- 核心链路优化方向正确：  
  `shadow` 从同步近似到异步后，热路径延迟显著下降。  
  `api_type auto` 探测缓存命中后，探测开销从网络级降到内存级。
- 对无 shadow 的直接路径没有显著负面影响。
